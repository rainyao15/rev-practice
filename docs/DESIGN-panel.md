# 可视化控制面板 —— 设计说明（0.3.0）

> 状态：**待确认**。确认后按此实现，不再改动方向。

## 为什么要做

现在的启动链是四层：`autostart.vbs` → `run-forever.cmd`（监督器）→ `node src/main.mjs` → 网易云客户端。
后果有三个，用户的抱怨都落在这三点上：

1. **有一个永远存在的控制台窗口**，没人知道那是什么；
2. **每次启用都要 UAC**，还要分清 `start.cmd` 和 `autostart.cmd`；
3. **没有任何状态反馈**——背景没出来时，用户不知道是桥接没跑、客户端没端口、还是壁纸选错了。

目标：一个常驻托盘的图形面板，负责「开关 + 状态 + 出错时看得懂原因」，把命令行降级为排障入口。

## 目录布局（便携）

```
netease-wallpaper\
  panel\
    BridgePanel.exe        编译产物（install.cmd 生成）
    panel-icon.ico
  src\                      桥接（node）
  native\                   SceneCapture / SceneAudio / autostart.ps1 / elevate.ps1
  runtime\                  ← 新增，运行时数据（.gitignore）
    state.json              桥接写给面板的状态
    panel.json              面板自己的偏好（上次启用状态、暂停到期时间）
    bridge.log              桥接日志（由面板重定向写入，单一写者）
    autostart.log
  config.json               端口与路径（已有）
```

日志从 `%LOCALAPPDATA%` 迁到 `runtime\`，搬家时若发现旧日志就保留一份 `bridge.old.log` 并在迁移日志里提一句。`pin.json`（`ne_pin` 的「最后由谁勾选」）仍在 `%LOCALAPPDATA%`，它属于「跨版本共享的用户状态」，不值得跟着目录走。

## 进程模型

```
计划任务 cloudmusic-wallpaper-bridge（登录时，HighestAvailable，每 5 分钟自检）
        └── BridgePanel.exe（托盘，唯一实例，命名 Mutex）
                └── node src\main.mjs（子进程，CREATE_NO_WINDOW，无控制台）
                        └── cloudmusic.exe --remote-debugging-port=9333
```

- `run-forever.cmd` **废弃**，监督逻辑搬进面板：子进程退出后 5 秒重启，连续 3 次失败则停手并把状态标红（原逻辑保留）。
- 面板退出（菜单「退出」）→ 先停桥接再退出；若此时桥接正在跑，弹一次确认「退出后背景会恢复成原生主题色」。

## state.json 契约

桥接每秒覆写（原子写：写临时文件再 `rename`）：

```json
{
  "version": "0.3.0",
  "pid": 12844,
  "heartbeat": "2026-11-05T23:20:01+08:00",
  "mode": "running",            // running | paused
  "ports": { "debug": 9333, "media": 2000, "scene": 2001 },
  "client": { "connected": true, "port": 9333 },
  "wallpaper": { "file": "miku.mp4", "kind": "video", "fps": 60, "pinned": false },
  "lastWarning": "the pinned wallpaper is gone, following the desktop wallpaper"
}
```

判定规则（全部在面板侧，互不依赖）：

| 观察 | 结论 |
| --- | --- |
| 文件不存在 / `heartbeat` 超过 5 秒 | 桥接未运行或失联 → 红灯 |
| `pid` 进程不存在 | 桥接已退出 → 红灯 |
| `mode == "paused"` | 已暂停 → 灰灯 |
| `client.connected == false` | 桥接在跑但客户端没端口 → 黄灯，提示用「彻底还原」再启用 |
| 心跳正常 + connected | 绿灯 |

## 窗口

固定 340×300（不可拉伸），标题栏正常，记住上次位置。

```
● 桥接        运行中 · pid 12844
● 客户端      已连接 · 端口 9333
● 当前壁纸     miku.mp4 · 视频 · 60fps
● 生效端口    9333 / 2000 / 2001

⚠ 找不到固定壁纸，已回退跟随桌面                ← 有警告时才出现

[ 暂停 ]                    [ 打开日志 ]  [ 彻底还原 ]
外观参数（不透明度/明暗/染色）请在 Wallpaper Engine 的壁纸属性里调
```

- 「暂停 / 启用」按钮的文案随状态翻转；点击后立即禁用并显示 `正在停止…`，最多等 5 秒。
- 「彻底还原」弹一次确认框，写明三件事：停桥接、重启客户端去掉调试端口、移除开机自启。
- 黄条只在 `lastWarning` 非空时出现，点击打开日志并滚动到含该文本的位置。

## 托盘菜单

```
打开面板
─────────
启用                    ← 勾选态，读 state.json
暂停 30 分钟            ← 已在暂停时显示「取消暂停（还剩 18 分钟）」
─────────
打开日志
彻底还原…
─────────
退出
```

暂停 30 分钟：停桥接，把到期时间写进 `runtime\panel.json`，面板 0.5 秒轮询到点即自动启用；重启面板后仍按到期时间判断（不因重启而丢失）。

## 失败姿势

| 情形 | 行为 |
| --- | --- |
| 计划任务建不起来（组策略/UAC 拒绝） | 面板以普通权限启动，状态行标黄「无法管理以管理員权限运行的客户端」 |
| 端口 2000/2001 被别的程序占用 | 桥接启动失败，面板显示红字与占用者提示，并指向 `config.json` 改端口 |
| 桥接连续 3 次启动失败 | 停止重试，红灯 + 「点此查看日志」 |
| 客户端正在跑但没有调试端口 | 黄灯；菜单「启用」会触发一次客户端重启（沿用桥接现有逻辑） |
| 面板被任务管理器杀掉 | 最多 5 分钟后任务拉起；期间双击快捷方式可立即启动 |

## 安装 / 卸载 / 迁移

**install.cmd**（一条龙，结尾提示「托盘里现在有个图标」）：

1. 检查 Node ≥ 18 与 .NET Framework 4；
2. 编译 `native\SceneCapture.exe`、`SceneAudio.exe`；
3. 编译 `panel\BridgePanel.exe`（`csc` + WinForms，零依赖）；
4. `node src\we-panel.mjs --all` 给所有壁纸写 `ne_*` 属性；
5. 注册计划任务（`HighestAvailable`，登录触发，每 5 分钟自检）；
6. 创建开始菜单快捷方式（指向 `BridgePanel.exe`）；
7. **迁移**：若发现旧任务指向 `wscript.exe … autostart.vbs`，就地替换为面板；若启动文件夹里有旧 `.lnk`，删除并记录。

**uninstall.cmd**：停面板 → 停桥接 → 删任务与快捷方式 → `we-panel.mjs --revert --all` → 删 exe → 保留 `project.json.bak-*` 备份与 `runtime\` 日志。

**autostart.cmd**：保留 `status/install/uninstall/start/stop`，内部改成操作面板而不是 vbs；输出第一行提示「图形面板是主入口，这里是无头模式」。

## 版本与验收

版本 **0.3.0**，Release 说明强调「启动方式变了，装完请重新跑一次 `install.cmd`」（迁移会自动完成，但用户需要知道这件事）。

验收清单：

1. 全新机器：解压 → `install.cmd` → 托盘出现图标 → 点「启用」→ 背景出现，全程 0 次 UAC；
2. 点「暂停」→ 1 秒内背景回到原生主题色，**歌不断**；
3. 杀 `cloudmusic.exe` → 面板在 10 秒内显示客户端失联，桥接自动拉起客户端后恢复绿灯；
4. 杀 `BridgePanel.exe` → 5 分钟内任务拉起，期间双击快捷方式可立刻恢复；
5. 「彻底还原」→ 背景回原生、客户端命令行里不再有 `--remote-debugging-port`、自启消失；
6. v0.2.x 覆盖安装 → 旧 vbs 任务被替换，日志出现「已从 v0.2.x 迁移」，背景正常。
